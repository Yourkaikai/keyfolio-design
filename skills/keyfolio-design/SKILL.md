# Keyfolio 设计语言

把界面做成一张受到柔光照明的桌面，内容是有厚度、能接光的物件。识别度来自光源、材质、排印与交互之间的关系。

这是从 Keyfolio v2 当前实现提炼的可复用设计 Skill。可以在原项目继续使用，也可在用户要求时迁移到新产品；迁移保留视觉关系，按目标产品重做信息结构。

## 先确定应用方式

- **原项目精修**：先识别用户指的元素与状态，复用现有 token、组件和光场。改动范围由当前请求决定。
- **新增页面或组件**：沿用同一表面、字体、圆角和状态语法，先解决内容层级，再决定哪里需要光。
- **迁移到其他产品**：沿用桌面、物件、光源的关系；按业务选择需要着色的实体。没有真实实体身份时，使用少量稳定的语义色即可，无需给每个区块发明一种颜色。
- **设计评审**：围绕具体元素指出问题和可执行修正；涉及实现时检查实际显示与交互。

在已有项目里，以当前用户要求和项目规范为准。参考中的尺寸是 Keyfolio 的桌面基准，不是手机、网页或其他产品的固定布局。

## 必须保留的视觉关系

1. **桌面只有一个环境光场。** 顶部最亮，向侧面和底部缓慢衰减，标题栏和正文处在同一个受光空间。颗粒轻微、静止，近白背景尤其要干净。
2. **彩色从物件的身份与光源产生。** Keyfolio 中厂商定义卡片主色、副色与光形；光从右下角聚起，向右侧和桌面扩散。文字区保留深色底，避免光把字托成灰雾。
3. **控件依靠中性色建立层级。** 明亮主题用深墨主按钮，暗色主题用近白主按钮；次操作轻描边或透明。身份色可延伸到对应详情和操作，错误与警告仍使用独立语义色。
4. **物件有接触关系。** 底影、边缘发丝线、局部高光和桌面溢光共同建立体积。暗色卡片也需要可读的背景与投影，不能把所有底层压成纯黑。
5. **排印承担主要信息层级。** Space Grotesk 对应拉丁 UI，PingFang SC 对应中文，JetBrains Mono 对应密钥和机器标识。标题、辅助信息与状态有稳定位置和明确字重。
6. **交互让光和物件响应意图。** hover 是短暂靠近，selection 是持续选择，press 是短促确认。快速掠过、滚动经过的卡片不应让整个房间反复换色。
7. **动效克制而连续。** 状态切换用确定的缓动，不使用弹簧回弹。尺寸、字重和反馈文案的变化不挤动邻近控件；仅在有必要时让物件轻微浮起。

## 落地时的取舍

先沿用目标项目的技术栈。SwiftUI 优先复用现有 KFTheme、KFFont、CardSurface、KFButtonStyle 等；Web 则把同一组语义值映射为 CSS variables 和组件状态。不要为迁移风格引入整套无关依赖。

先建立静态完成态，再补 hover、selected、pressed、focused、disabled 和必要的反馈。光场的成本不适合目标设备时，用预渲染或静态柔光保留层次；无法完成的动态部分明确说明，不把近似实现称为完全复刻。

交付以任务为准：设计探索给出可审查的方案；实施任务推进到能运行、能交互的结果。界面验证应覆盖本次改动涉及的明暗主题、文本长度和关键状态，并实际检查变化后的显示；源码、构建和截图分别说明了什么，不互相代替。

## 常见偏离及修正

| 偏离 | 修正方向 |
| --- | --- |
| 每个面板都加彩色渐变或光晕 | 把颜色收回到有身份的内容对象，环境光服从当前对象 |
| 大面积模糊玻璃盖住背景 | 用明确表面、接触阴影、细线和局部受光建立层级 |
| 给整个界面套纯黑、禁蓝或禁纯白规则 | 按本 Skill 的实际明暗 token 与卡面例外处理 |
| hover 只把整张卡涂亮，或让光扫过文字 | 保留深色字底，增强角落主光、副光和溢光 |
| 健康状态、装饰徽章和主操作一样抢眼 | 正常状态收敛到小圆点，让异常标签承担提示 |
| 用弹簧、持续闪烁或整屏同步呼吸增加活力 | 使用固定缓动、分散相位和与操作相关的一次性光反馈 |
| 精修一个控件时顺手重排整页 | 先完成该控件及其必要关联状态，保留用户指定范围 |
